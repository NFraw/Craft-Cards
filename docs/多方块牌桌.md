# 多方块斗地主牌桌

将 `crafty_cards:ddz_table` 在同一高度水平拼成完整矩形，即组成一张桌。**整桌最多 9 个方块**，支持单格、2×3、3×2、3×3、1×9、9×1 等矩形；2×5、3×4 等超过 9 格的尺寸不允许使用。正常物品放置会拒绝第 10 格，也会阻止用一格把两片桌子连接成超过 9 格的结构，物品不会被消耗。摆放过程中允许暂时呈 L 形，但必须补成完整矩形才能使用。

只连接四个水平方向上同一注册类型的牌桌；斜角接触、上下堆叠不合并。通过命令或旧存档形成的超限结构不会被自动删除，但不能开局；L 形、带洞结构也会提示修正，不能当作多张单格桌分别入局。

## 玩家操作

- 点击任意组成块，都在同一桌加入、叫分、出牌、过牌或离开；整桌只有三个座位和一份入场押注。
- 空桌时，附近任何玩家都可 Shift+右键任意组成块编辑同一套筹码配置；有人入局后，未参局玩家使用该操作切换观战。
- 桌布连续铺设，内部木框替换成绿色桌布，仅整桌外圈保留木框。出牌与筹码位于整桌几何中心。
- 筹码和桌面牌从各自的实际显示位置取环境光照，避免实心桌体内部的暗光照让展示物变黑。
- 等待阶段的信息层（包括“不需要筹码”和“筹码还没配”提示）显示 5 秒后整块隐藏；重复快照不会续时。再次右键同一桌可重新显示 5 秒，人数或筹码状态改变时重新提示。隐藏只影响显示，不会退局或清除订阅，开局后正常显示叫分与出牌 HUD。
- 入局、观战和配置距离从整桌最近的边界计算，站在大桌远端也可使用。入局后继续允许自由走动。
- 任一组成块被拆除、被其他方块替换，或旁边增加牌桌改变结构时，原牌局结束，原物押注分别退还，扑克牌回收，参与者、观战者和配置持锁者收到终止快照。不会把两个活动牌局的物品池直接混合。扩建/合并后需重新入局。
- 保存或关闭过配置、仍缓存筹码预览的玩家也会收到终止快照；这类清理快照不包含手牌数据。客户端发现已加载的组成块消失时会清除旧预览，避免桌子拆掉后悬浮筹码残留；未加载的区块不会被误判为拆桌，结算结果仍保留到玩家关闭。
- 两张同类桌如果不希望合并，水平至少空一格，或放在不同高度。不同类型的游戏牌桌不连接。

## 配置与旧存档

整桌西北角（X 最小、Z 最小的那格）是主坐标。筹码、底注、门槛由牌桌方块实体持久保存，不归某个玩家所有。空桌时任何附近玩家均可编辑，一次仅一人持有临时编辑锁；其他玩家不能抢锁、保存或释放别人的锁。持久配置复制到各组成块，锁只保留在当前主方块、不落盘。

“保存并关闭”成功后立即释放锁，ESC/返回也释放锁；编辑者走远、掉线或达到 120 秒上限时自动释放，并通知其客户端关闭界面。编辑期间暂缓新玩家入局；有人入局后禁止修改参数。旧存档的 Host/HostName 被忽略并在重新保存时移除，筹码配置保持原值。

向西或向北扩建、拆掉主方块后，存活成员仍保留配置。新主角未配置时，从原有成员继承；合并两张已配置的桌时，采用西北角已有配置，另一桌的活动押注先正常退还。拆分后若形成两张合法矩形，两者分别成为独立牌桌，并继承原桌配置；需要不同配置时各自修改。

旧存档中的方块实体数据不需要手动迁移。加载时会刷新新增的四向连接属性。使用跨区块的桌子时，结构及相邻边界区块须已加载；结构搜索不强制加载区块。活动桌的结构不再完整加载时，会在服务端结构检查中结束牌局并退还押注。

网络协议升级为 3，快照使用 canEditTable 表达当下编辑能力，不再表达永久房主身份。客户端与服务端都需使用此次构建的模组。

## 实现入口

| 模块 | 文件 |
| --- | --- |
| 纯矩形识别、上限、距离 | `game/DDZTableLayout.java` |
| 服务端结构解析与配置继承 | `game/server/DDZTableStructure.java` |
| 四向状态、放置/移除回调 | `block/BlockDDZTable.java` |
| 加载刷新、配置持久副本 | `blockentity/DDZTableBlockEntity.java` |
| 全部动作统一主坐标、结构清理 | `game/server/DDZTableManager.java` |
| 三人会话、押注与通知 | `game/server/DDZSession.java` |
| 整桌尺寸快照 | `network/payload/GameStatePayload.java` |
| 任意组成块交互 | `client/ClientDDZData.java`、`client/DDZGameHud.java` |
| 整桌中心与裁剪 | `client/WorldPlayedCards.java`、`WorldTableChip.java`、`TableRenderBounds.java` |
| 连接模型 | `assets/crafty_cards/blockstates/ddz_table.json`、`models/block/ddz_table_*.json` |

`DDZEngine` 的发牌、牌型和计分逻辑保持不变。

## 验证

```powershell
.\gradlew.bat test runGameTestServer --no-configuration-cache
python -m unittest discover -s tools -p test_ddz_table_models.py
powershell -ExecutionPolicy Bypass -File .\build-target.ps1
```

`DDZTableLayoutTest` 覆盖统一坐标、转置矩形、斜角、L 形/空洞/超限和最近边界距离。`DDZMultiTableGameTest` 覆盖六格统一入局和完整出牌结算、一次收注、任意成员拆除退款与所有接收者关闭通知、主坐标变化、配置与快照序列化、非法坐标、旧状态加载修复、两桌合并退还两份物品池和远端入局。

`tools/test_ddz_table_models.py` 检查全部 16 种连接状态无顶面空洞或重叠，并验证多种矩形仅有最外围木框、物品栏与手持变换及贴图引用。
