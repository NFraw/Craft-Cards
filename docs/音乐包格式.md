# 音乐包格式与制作

> 适用版本：Crafty Cards 1.0.0；三加载器共用此音乐包格式，实际安装包按 Minecraft 版本和加载器选择。

**模组本身不含任何音频文件。** 音效与 BGM 全部来自**音乐包**——包由玩家自己做、自己装。
模组 jar 不附音频；仓库的 [三个 1.21.1 学习样本](../learning-soundpacks/README.md)附有真实音频和包清单。录音来源与再分发权尚待核查，详见 [音频权利说明](../release-materials/AUDIO-RIGHTS.md)；玩家也可用 **`tools/soundpack_maker.py`** 以自己有权使用的素材制作音乐包。

- [悠闲版本（含音频）](https://github.com/NFraw/Craft-Cards/releases/download/v1.0.0/crafty-cards-1.21.1-relaxed-soundpack.zip)

## 一、放在哪

```
config/crafty_cards/soundpacks/
└── 3f9a2c71/               ← 目录名 = 包 id：由制作程序随机生成，玩家不填也不用记
    ├── pack.json           ← 清单（必需）
    ├── pass_1.ogg
    ├── pass_2.ogg
    └── ...
```

**包 id 由制作程序生成**（8 位随机字符），玩家填的是 `pack.json` 里的**显示名**与**作者**——
游戏里的音乐包列表显示的就是这两项，你按显示名认自己的包。

如果要修改已有音乐包，在制作工具中点“导入包目录…”或“导入 ZIP…”。程序会读取原包的音频映射与权重，在界面中供你修改；导入不写输出目录。检查审查页后手动点击“生成音乐包”，会生成一份新包，原包不变。三包合集 ZIP 请先解压，再逐个导入包目录。

为什么不让玩家填 id：一个目录里只放得下一份 `pack.json`，两个包共用 id（比如都取名 `my_pack`）
时，后构建的会把前一个的清单**顶掉**——那个包在游戏里就"没声音了"，而文件还在、列表里还看得见，
很难查。随机 id 让两个包撞不到一起，所以同一台机器上可以并排装好几个包、随时切换。

> 手动改目录名 = 换了一个包：游戏里记的选用记录（`activePack`）会失配（包还在，但选中的是旧 id）。
> 要改包的名字请改**显示名**，别动目录名。

游戏内 **Mods → Crafty Cards → Config → 音乐包**：点「扫描」发现新包 → 选用 →「保存并应用」。
也可以直接改 `config/crafty_cards/sounds.json` 的 `activePack` 字段。

## 二、音频键：以"什么声音"为单位，而不是"哪个文件"

一个**音频键**对应游戏里一个可被触发的音效。共 61 个，分三组：

### 音效（7 个）

| 键 | 触发时机 |
|---|---|
| `deal` | 开局发牌 / 洗牌 |
| `bid` | 叫分确认 |
| `play` | 出牌（通用；该牌型没有语音时用它） |
| `bomb` | 出牌（炸弹 / 火箭） |
| `pass` | 过牌（"不要"） |
| `win` / `lose` | 结算：自己获胜 / 失败 |

### 背景音乐（6 个，循环播放）

| 键 | 触发时机 |
|---|---|
| `bgm_waiting` | 等待玩家加入 |
| `bgm_playing` | 叫分 / 出牌进行中 |
| `bgm_clutch` | 有人只剩 **3 张以内**的牌（残局紧张段） |
| `bgm_rocket` | **王炸**打出来之后（持续到下一轮重新出牌） |
| `bgm_win` / `bgm_lose` | 结算：自己获胜 / 失败 |

> `bgm_clutch` / `bgm_rocket` 是后加的两首：**没配也不会有问题**。播放时按
> `王炸 → 残局 → 对局进行中` 依次往下找第一个配了文件的键，一个都没有才不播——
> 老音乐包在这两个时刻会继续放「对局进行中」。两者同时成立（有人快出完 + 刚炸完）时王炸优先。

> `win` / `lose` 与 `bgm_win` / `bgm_lose` 都在结算时触发，但**是两组不同的键**：
> 前者是结算那一刻响一次的**音效**，后者是结算阶段**循环**的背景音乐。游戏界面与制作程序里
> 它们的中文名分别写作「结算胜利」与「BGM：结算胜利」——那个前缀就是把两组区分开的依据。

### 牌型语音（48 个，出牌时按牌型播报）

| 键 | 含义 |
|---|---|
| `dan1` … `dan15` | 单张：1=A，2~10 为牌面，11=J，12=Q，13=K，14=小王，15=大王 |
| `dui1` … `dui13` | 对子：1=A … 13=K |
| `tuple1` … `tuple13` | 三条：编号同对子 |
| `sandaiyi` | 三带一 / 三带二 |
| `shunzi` | 顺子 |
| `liandui` | 连对 |
| `feiji` | 飞机 |
| `sidaier` | 四带二（单） |
| `sidailiangdui` | 四带二（对） |
| `wangzha` | 王炸 / 火箭 |

**优先级**：出牌时先看该牌型的语音键有没有文件，有就播它；没有才用 `play`（通用出牌）；
都没有则用原版音效。BGM 键按 `王炸 → 残局 → 对局进行中` 回退，全都没有才不播。

> 键名同时是配置字段名与音效 id，少一层要记的映射。

## 三、清单格式（pack.json）

```json
{
  "version": 2,
  "name": "我的斗地主音效包",
  "author": "你的名字",
  "description": "自己录的语音",
  "sounds": {
    "pass": [
      { "file": "buyao_1.ogg", "weight": 3 },
      { "file": "buyao_2.ogg", "weight": 1 },
      "buyao_3.ogg"
    ],
    "dan1": ["danA.ogg"],
    "bgm_playing": ["normal.ogg"]
  }
}
```

- `sounds` 的键是**音频键**（上一节那 61 个），值是**文件列表**。
- 列表元素两种写法：文件名字符串（权重 1），或 `{ "file": "...", "weight": N }`。
- `weight` 是**正整数**（1~99），表示同一键下被挑中的相对概率：权重 3 与 1 就是 3:1。
  真正的随机由游戏引擎完成（权重写进生成的 `sounds.json`）。
- `name` / `author` / `description` 可省（省了用目录名当显示名）。
- **没写的键就没有声音**（音效退回原版音效，BGM 按回退链往下退、全都没配才不播），所以不必填满 61 个键。
- 文件名只接受英文/数字/`.`/`_`/`-` 且必须以 `.ogg` 结尾——这条限制防的是路径穿越
  与配置注入，游戏会拒绝不合规的名字并记一条日志。
- 老版本（没有 `version`、用 `soundEffects`/`bgm` 两张表、一个键一个文件）的包仍然能读，
  但用制作程序重新导出会升级成版本 2。

### 音频格式

**必须是 Ogg Vorbis**（Minecraft 只支持它，不支持 MP3）。单声道更适合音效；
背景音乐建议 ≤ 44.1kHz 立体声、码率 96~128 kbps（模组体积要克制）。

## 四、制作程序（批量命令行与图形界面）

```bash
python tools/soundpack_maker.py --cli <源目录> [--name 显示名] [--author 作者] [--desc 说明] [--out 输出根目录] --dry-run
python tools/soundpack_maker.py --cli <源目录> [--name 显示名] [--author 作者] [--desc 说明] [--out 输出根目录]
python tools/soundpack_maker.py                                       # 打开图形界面
```

音频较多时，先按键名整理文件，再用 `--dry-run` 预览所有映射、权重及无法识别的文件；
预览不创建目录或写文件。核对后去掉 `--dry-run` 批量生成。需要助手协助整理，可复制
[快速制作音乐包提示词](Harness音乐包制作提示词.md)。程序会：

1. 把 `.mp3` / `.wav` / `.flac` 等**转码**成 Ogg Vorbis；
2. 按你的归类写出 `sounds`（含权重）；
3. 自动分配随机**包 id**，把包落在 `config/crafty_cards/soundpacks/<包id>/`。

少量文件也可以用图形界面：填显示名 / 作者 / 说明，在音频键列表中逐条添加文件和设置权重，
点「审查配置…」核对，再点击「生成音乐包」。添加时只暂存来源；生成时才写入目录。

包 id 由程序生成、界面里不给你填（理由见第一节）。想做另一个包就点「新建包」：它清空当前内容并
换一个新 id，所以**多次构建出来的是多个互相独立的包**；同一个包想改内容就别点「新建包」，
直接改完再构建，会写回同一个目录。

命令行模式是同一套逻辑的无界面调用，方便脚本化与批量重做。包 id 一般不用写（自动生成）；
只有脚本要往**固定目录**里重写时才显式传一个——这时如果那个目录里是**别人的包**，程序会直接
报错而不是覆盖它。省了 `--name` 就用源目录名当显示名。

图形界面里每个文件都可以「试听」：用**系统默认播放器**打开该文件（本程序不内嵌播放器），
听到的音质、音量、输出设备都跟你平时听的一致。

「使用说明」会在程序启动时**自动弹出来并置顶**（关掉后右上角那个按钮随时能再打开），
里面写着完整的操作流程与键的清单含义，第一次用就直接照着看。

> **包的增删改只在这个程序里做**：游戏内只读取和选用包、调整总开关与共用音量；
> 各文件权重由包内 `pack.json` 决定，游戏不会写回包。

## 五、优先级与生效方式

游戏侧能配的只有三项（都在设置主页的 **音乐包** 页里；`/craftycards sounds` 可直接跳到那一页）：

| 项 | 说明 |
|---|---|
| 总开关 | 关掉后音效退回原版、BGM 不播、音乐包也不加载 |
| 音量 | 音效与 BGM 共用一个音量 |
| 选用哪个包 | 点「扫描」发现新包、选中、点「保存并应用」生效 |

**包的清单就是全部音频来源**：每个键的候选文件只有一个来源——当前音乐包。
游戏侧不再提供"逐键指派文件 / 逐条调权重 / 试听"这类入口（历史上曾有"自备单文件"那条路，
已删除）。要调权重就改包：把某个文件的权重写小（或从清单里去掉）就等于"少播/不播它"；
某个键在包里没有条目，就等于这个键没有声音，会落到下一档
（牌型语音 → 通用出牌 → 原版音效）。

BGM 的声道（`bgmCategory`）与"是否压低原版音乐"没有界面入口，需要时直接改
`config/crafty_cards/sounds.json`（改完重启生效）。

生效机制：模组会把当前生效的文件**复制进一个自动生成的资源包**
（`config/crafty_cards/sounds_pack/`，含带权重的 `sounds.json`），并以最高优先级注入游戏。
该目录每次启动、每次「保存并应用」都会重写，所以换包、改权重、加文件都会自动跟上。

### 听不到声音时先查这两处

1. **音量滑块**：BGM 默认走原版「玩家」声道（`bgmCategory = players`，这样播放 BGM 时才能把
   原版背景音乐压低到 10% 而不连自己一起压掉）。若「玩家」滑块为 0，BGM 听不到——
   调高滑块，或把 `bgmCategory` 改成 `music` / `ambient` / `master`（改回 `music` 就不再压低原版音乐）。
2. **有没有装包**：模组不含音频，没装包也没加本地文件时，音效就是原版音效、BGM 静音。
   配置界面在"一个键都没有音频"时会在底部提示。
