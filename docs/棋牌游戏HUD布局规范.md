# 棋牌游戏 HUD 布局与风格规范 v1

定稿日期：2026-10-21。适用目标：NeoForge / Minecraft 1.21.1、Java 21。
本规范以斗地主现有世界叠加 HUD 为基准，炸金花已接入共享坐标与视觉组件；以后新增牌类游戏沿用本规范。

## 1. 统一原则

普通对局保留世界画面。顶部显示公共局势，中央保留牌桌与世界观察空间，底部显示本人操作与手牌，结算使用全屏半透明遮罩。
固定坐标体系、分区、间距、颜色语义和输入含义；手牌的排法、人数、公共信息字段与可用行动由玩法决定。

斗地主保留多张扇形手牌、选中上抬、底牌及可选的上轮出牌区；炸金花保留三张平铺手牌、逐张翻牌、投入与余额、比牌目标选择。
两种游戏的牌面可见性各自服从服务端规则，共用渲染组件不意味着共用亮牌权限。

世界牌桌也属于这套识别规范：斗地主深蓝桌布、炸金花酒红桌布，各自使用独立图集；新游戏共用几何时也必须覆盖自己的材质ID。资源约定见[各玩法专属牌桌贴图](牌桌专属贴图.md)。

## 2. 唯一坐标体系

所有数值先在高度为 **320** 的设计画布计算，宽度随实际 GUI 宽高比变化，再整体缩放回 GUI。
共享入口为 `CardGameHudLayout.viewport`；斗地主的 `HudHandMetrics.viewport` 委托同一入口，炸金花渲染同样使用它。

```text
s = GUI高度 / 320
设计宽度 = round(GUI宽度 / s)
GUI坐标 = 设计坐标 × s
```

探针、线框图和实机都执行这次换算。报告跨游戏比较必须注明单位，不能把 GUI 高度直接代入某一游戏的设计坐标公式。

## 3. 固定分区与间距

以下均为设计像素，y 表示文字顶边。

| 区域 | 位置 / 规则 |
|---|---|
| 游戏名称 | 顶部居中，y=4 |
| 阶段、行动者、倒计时 | y=16；倒计时与整行共同居中，按紧迫程度着色 |
| 公共局势 | y=30；如地主、锅底、基准注 |
| 等待阶段补充信息 | 可使用 y=46；等待状态不展开一整套对局信息 |
| 反馈 | 操作行上方26，即默认 y=114；只在有反馈时出现 |
| 操作提示 | 操作行上方13，即默认 y=127 |
| 行动选项 | 设计高320减180，即默认 y=140，保持位置稳定 |
| 本人信息 | 可选；在手牌上方，炸金花用于明暗状态、投入、余额 |
| 本人手牌 | 底部居中；默认底边距30，同时保证实际 GUI 中至少留26给快捷栏 |
| 结算关闭提示 | 默认 y=266，即设计高减54；避开快捷栏及物品名称 |

竖向顺序固定为“反馈 → 提示 → 选项 → 本人信息（可选）→ 手牌”。
选项行不得挤入本人信息或手牌，空间不足时以实际牌框上沿约束位置；兼容入口保留 `minOptionRowY()` 防止撞顶。操作行整块必须位于准星安全区上方，不能只检查与手牌的距离。
布局计算必须包含焦点框、扇形外扩与选中上抬。检查各元素分别在屏内还不够，还要检查相互遮挡。

## 4. 视觉风格

沿用 Minecraft 原版字体、扑克牌模型和世界叠加方式。文本按小块深色底衬承载，保持牌桌周围的世界可见。
操作采用等宽文字选项、项内居中与金色焦点，普通对局不另起一套大面板按钮风格。

| 语义 | ARGB |
|---|---|
| 标题、普通选项 | `FFFFFFFF` |
| 阶段、次要公共信息 | `FFAAAAAA` |
| 当前焦点、赢家、关键身份 | `FFFFD700` |
| 可操作提示 | `FF55FF55` |
| 错误反馈 | `FFFF5555` |
| 禁用选项 | `FF666666` |
| 结算中的本人身份 | `FF7FD4FF` |
| 文字底衬 | `E0101418` |
| 焦点底衬 | `66000000` |
| 结算全屏遮罩 | `A0000000` |

焦点与已选是两种状态：焦点用金色边框，已选牌用上抬或状态边框标识；颜色之外必须有文字或几何区别。
倒计时继续复用 `TurnCountdown`：最后10秒橙色、5秒红色，无限时时不显示。

## 5. 选项与文字

复用 `HudOptionBar`：同一行等宽，首选项宽为“最宽标签+12”，下限40；外侧边距8，焦点框左右各外扩2。
窄屏先压缩空白。行动名称、费用、倒计时与净得失数字应优先完整展示；长玩家名允许裁短，但不能因此把两个目标变成无法区分的选择。
未来游戏若有更多行动，应拆子菜单或分页，再补相应测试，不得无限压缩成只有几像素的点击目标。
当前输入以滚轮定位、右键牌桌确认为准，选项宽度检查不等于已经验证了鼠标直接点击按钮。

## 6. 手牌模型

共享扑克牌模型 `card_base.json` 的完整横向范围为2.9–13.1，即宽 **10.2**，长边为16。
缩放应为 `牌宽 × 16 / 10.2`，布局高度使用同一结果四舍五入。中央牌面宽9不能代替整个模型宽度。
`CardVisuals`、`RenderConfig` 和 `ZJHLayout` 从 `CardGameHudLayout` 取得换算，焦点框按同一尺寸绘制。
多张牌允许有意叠放，但点数/花色的辨认区、焦点和已选状态必须可见；三张牌默认完整平铺。

## 7. 结算

结算内容在顶部与关闭提示之间居中，顺序为结果、必要的下注摘要、玩家结果行。
玩家较多时先压缩空白和次要文字；行高不足22时使用一行结果，优先保留净得失数值。
斗地主继续展示三家剩余手牌，炸金花正常结算展示服务端下发的全体三张手牌。
成功结算由服务端释放牌局，客户端保留结果供查看；共同支持右键关闭结果。斗地主保留原有左键关闭行为。
关闭结果不得误加入下一局，HUD 消失与服务器座位释放需分别验证。

## 8. 新游戏接入约定

新游戏提供状态、本人手牌、公共局势、行动列表、可选本人信息、反馈和结算行；复用画布、选项、文字底衬、模型换算与底部安全区。
不复用其他游戏的引擎、押注政策或隐私政策；不通过新增游戏修改既有 payload 枚举的编码顺序。
布局函数保持不依赖 Minecraft 的可测试边界。新增布局应消费共享计算结果，不复制常量或先画一套再为探针另抄一套。

## 9. 验收口径

至少覆盖 GUI 320×180、427×240、640×360、960×540，以及真实普通窗口、小 GUI 视口和全屏。
320×180是探针的压力输入，不能直接声称原版一定允许该GUI尺寸：本机1280×720截图实际为427×240、缩放3；截图旁的JSON记录实际窗口和GUI尺寸。
验证等待、本人/他人回合、焦点、已选或翻牌、目标选择、胜负结算与关闭，覆盖人数上下限、长姓名、较大费用及无筹码分支。
每一轮交付明确区分：纯布局探针、单元测试、服务端 GameTest、真实客户端联机、逐图视觉检查。
真实截图必须先查看再写结论；报告注明已实测的场景与未覆盖的场景，不把线框图或模拟玩家测试写成实机通过。

本轮实际测试覆盖见《HUD统一与实机测试报告-2026-10-21》。本规范的完整验收矩阵不等于本轮全部场景均已实机覆盖。
