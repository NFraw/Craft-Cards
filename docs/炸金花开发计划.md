# 炸金花开发计划

2026-10-21 后续补充：基础玩法已有实现，但同类炸金花桌的相邻融合仍未实现。配方收口、固定配色及拼桌实施和验收顺序，以 [牌桌配方与拼桌状态及后续计划](牌桌配方与拼桌状态及后续计划.md) 为准。

状态：基础实现已加入，真实客户端与视觉验收按用户要求由用户进行。目标：NeoForge / Minecraft 1.21.1 / Java 21。操作与验收项目见 [炸金花玩法与验收](炸金花玩法与验收.md)。

## 1. 目标与现状

新增与斗地主并列的联机棋牌游戏：独立的炸金花牌桌、规则、HUD、每桌配置和结算；共用现有扑克牌资源与基础设施。首版支持 2–6 人，默认 3 人起局，不增加单人 AI。

本计划依据用户提供的规则及当前源码制定，并按最新要求只保留炸金花的基础特色。网页材料中的地方变体与附加奖励不直接作为功能清单；实现建议以本计划的简化规则表为准。

当前可复用的基础：

- `CardStacks` 的只读牌面/牌背缓存、现有扑克牌模型与贴图。
- `ConfigScreenBase`、`ConfigLayout`、倒计时显示思路、音乐包加载管线。
- `TableKey`、`platform/Network` 的发送接缝、平台事件与公共逻辑分离的结构。
- 斗地主按接收者构建快照、主线程处理操作、配置锁、原物筹码保管的经验与测试方法。

当前不能直接当作公共组件的部分：`DDZSession` 包含斗地主规则及赔付方式；`WorldHandCards` 直接读取 `ClientDDZData` 且固定遍历三人；`Network.Bridge` 的参数绑定斗地主 payload。需要小范围拆分，不能只把三人常量改成六人。

2026-10-21 检查到本地已有安装 JAR 为 497,651 字节（约 486 KiB），仅作包体基线，不代表本次重新构建或最新源码构建结果。

## 2. 首版只保留基础玩法

范围按用户最新要求收敛：保留发三张暗牌、暗注明注、看牌、跟注、加注、比牌、弃牌和锅底结算。规则数值采用下面的简化建议，不混入地方奖励或复杂衍生机制。

| 项目 | 首版建议 |
| --- | --- |
| 牌与人数 | 52 张、无王、每人三张，2–6 人 |
| 开局 | 牌桌保存配置后开放加入；加入即就绪，达到配置人数后自动校验距离与筹码、统一投入底注并发牌。无需房主、准备或手动开始 |
| 行动顺序 | 首局随机庄位，之后按座位轮换庄位，由庄家下一位开始；逆时针依次行动，不引入额外庄家权益 |
| 牌型 | 普通顺序为豹子 > 顺金 > 金花 > 顺子 > 对子 > 散牌 > 特殊；特殊为至少两种花色的 235，同花 235 是金花。有效参比手牌中同时存在特殊与豹子时，特殊获胜，不管是否还有其他牌型 |
| 点数 | 普通比点 A 最大；沿用最新材料的顺子顺序 QKA > A23 > KQJ > … > 234；KA2 不成顺 |
| 同类比较 | 豹子比点数；顺子/顺金比顺子等级；对子先比对子点数再比单牌；金花/散牌按点数降序逐张比，不比花色 |
| 底注 | 每人开局投入 A，初始暗注基准 B=A，不另分底金和底注 |
| 翻牌 | 按实机反馈更新：本人回合先选择“明牌”按钮进入选牌，再滚轮定位手牌、左键选中、右键牌桌翻开选中的牌。首次成功翻开任意一张即由暗牌转为明牌，不结束回合、不重置倒计时；随后可继续跟注、加注、比牌或弃牌 |
| 跟注 | 未看牌支付 B，已看牌支付 2B，费用全进锅底 |
| 加注 | 暗注基准只用 A、2A、4A 三档；选择高于当前 B 的一档，并支付本人明暗状态对应的注额；不额外再扣一次跟注 |
| 比牌 | 全桌完成前两轮行动后，从第三轮起在本人回合选择任一其他在局者。支付本人当前跟注额的两倍，暗牌 2B、明牌 4B；目标不额外付费。输家直接弃牌出局，赢家留在牌桌上；平手由发起者输 |
| 比牌后续 | 比牌作为一次完整行动，结束后轮到下一名在局者；不增加获胜者当回合再次加注的分支 |
| 弃牌/超时/掉线 | 已投入锅底的筹码不退，玩家退出本局，其他人继续；不追加赔款 |
| 正常结束 | 只剩一名在局玩家，获得全部锅底 |
| 结束保障（开发采用的简化方案） | 本桌设置固定的个人累计投注上限；底注、下注、比牌费用都计入。一次合法付费使任一人恰好到达上限后立即系统开牌；若下一次合法付费会超过上限，则不扣该笔费用，直接系统开牌。开发前已说明采用此简化收尾，待用户体验后如需修改再调整 |
| 系统开牌 | 仅比较仍在局者，最高牌获胜；同牌同点平分锅底，整数余数从行动起点起按逆时针在赢家间逐个分配 |

以上属于简化版规则建议，实施时将规则表与金额示例固定进说明和测试。人数默认 3 人起局、下注三档及上限的具体默认值可用实现阶段的小范围调整，不增加一套可任意拼装规则的设置系统。

首版范围外：喜金及准备金、豹子/顺金额外收费、按最少筹码的 40% 动态封顶、100 倍底注开牌禁手、独立的每轮比牌次数配额、比牌获胜后追加行动、all-in、边池、抽成、单人 AI、多套地方规则切换。特殊 235 的大小规则保留，与附加奖励无关。

### 已明确的大小判定与轮次

- 普通牌型按上述顺序比较；同类按点数比较，对子先比对子点数，再比单牌。顺子与顺金为 QKA > A23 > KQJ > QJT > … > 234。
- 主动双人比牌只比较本次双方：特殊 235 胜豹子，输给其余普通牌型；同牌同点由发起者输。第三人的暗牌不影响此次比较，避免泄露其是否持有豹子。
- 系统开牌仅收集仍在局者的手牌；若其中同时存在豹子与特殊 235，所有特殊 235 获胜，否则按普通顺序选最大牌。最大牌同牌同点平分锅底。此前已弃牌或比牌出局者不重新参赛，其手牌也不触发此次特殊判定。
- 完整双人规则存在“特殊胜豹子、豹子胜顺金、顺金胜特殊”的循环，不能用普通排序取全桌第一名。牌型分类、双人比较与多人开牌分别实现与测试。
- 一轮为行动顺序绕桌一圈；跳过已出局座位，不因弃牌重新起算轮次。翻牌不结束行动、不增加轮次。第 1、2 轮不提供比牌操作，第 3 轮开始才提供，并由服务端再次校验。

“喜金”完全不进入首版实现，不保留隐藏开关、占位字段、扣费接口或准备金。实现中只围绕一个锅底结算；赢家牌型只决定大小，不改变赔付金额。

无物品筹码模式仍使用同一套虚拟注额进行游戏；结束只展示分数，不移动物品。斗地主原有 `chipRequired=0` 约定保持原义，新游戏区分物品筹码开关与逻辑注额。

## 3. 玩家体验

新增单方块炸金花牌桌及独立配方，尽量引用现有桌体模型和贴图，通过名称与小幅视觉标识区分。斗地主牌桌入口和存档标识保留。

- 右键加入，Shift+右键按服务端身份分流为离开、配置或主动观战。
- 使用世界叠加 HUD，显示三张手牌、明暗状态、座位、存活状态、当前基准注、本人操作费用、锅底、预算余额、倒计时。
- 对手信息移到世界中的玩家身旁，不再在屏幕侧边列出六人 HUD。仍在局的玩家身前三张牌按公开翻牌张数显示：0 张为三张牌背，1 张为一张空牌加两张牌背，2 张为两张空牌加一张牌背，3 张为三张空牌。空牌复用 `common/src/main/resources/assets/crafty_cards/textures/item/cards/card_empty.png`（资源位置 `crafty_cards:textures/item/cards/card_empty.png`），不复制图片。
- 世界文字显示累计投入、最近行动以及当前行动提示；庄家头顶显示金黄色 `[ 庄 ]` 标记。出局后立即撤去该玩家的三张世界牌，原位置改为“出局”。翻牌数量仍保留在服务器记录中，但不再为出局者绘制三张状态牌；结算再统一展示全员真实手牌。
- 初始三张牌都显示牌背。选择“明牌”进入选牌后，滚轮定位某张手牌，左键切换选中状态，右键牌桌请求翻开选中的未翻牌；收到服务端确认后显示这些牌面。这里按逐张选择解释交互：没有选中的其他牌仍显示牌背，不能因客户端已收到数据提前显示。
- 只要首次成功翻开任意一张，服务端把 `hasLooked` 从 false 改为 true，此后整手牌的下注都按明注计算；不要求三张全翻才变明牌，不能翻回暗牌恢复低价。服务端另记已翻开的牌位，只给本人下发对应牌面。
- HUD 将手牌焦点和行动焦点区分显示，滚轮用于定位手牌或可用行动；手牌上的左键选择不直接下注，拦截该点击以免破坏世界。尚未翻满三张时保留明牌、跟注、加注、加倍、弃牌五项；实际翻开第三张后移除明牌，剩余四项。每次通过明牌入口进入选牌，确认翻牌后回到行动区；首次翻牌即按明注收费。只有选牌模式才移动手牌焦点。
- 只有本人回合才提供选牌翻牌交互；其他时间可查看自己已经翻开的牌，不能继续翻新牌。没有待翻选牌时，可选择跟注、加注或弃牌；第三轮开始才加入比牌操作。右键牌桌确认，加注选择档位，比牌选择目标，始终显示当前实际费用。未选牌且未选行动的右键不默认跟注或弃牌。
- 不同游戏共用输入路由，一名玩家同一时刻只参加一桌；主动观察另一桌前先退出当前观察，避免多个 HUD 抢输入。
- 正常结算后 HUD 展示本局所有玩家的全部三张手牌，包括未翻牌、主动弃牌、比牌出局、离开或掉线者，并显示赢家、结束原因及每人投入/所得/净变化。只剩一人获胜也执行全员亮牌；结算成功自动退局并释放牌桌，客户端保留结果供查看，右键任意位置关闭；重新加入达到配置人数即自动开局。

本桌仅保留必要设置：起局人数、底注、个人累计投注上限、行动时限、筹码类型与物品筹码开关。下注三档由底注自动派生，不单独配置；预算覆盖个人投注上限，所有金额运算做边界校验。既有配置布局与临时编辑锁超时机制复用，不保留炸金花房主身份，不在 `server.json` 中堆一批会误改斗地主的同名字段。

### 回合内的先后顺序

1. 先校验牌局仍在进行、本人仍在局且轮到本人；非本人回合不执行翻牌或行动。
2. 右键牌桌时，若有选中的未翻牌，优先且仅提交翻牌请求，不在同一次点击附带跟注、加注、比牌或弃牌。
3. 服务端验证牌位与本次请求，更新已翻牌位及 `hasLooked`，向本人下发牌面，向其他接收者更新明暗状态。翻牌本身不扣费、不推进回合、不延长倒计时。
4. 客户端收到确认后清空选牌，并按新状态刷新行动费用；确认到达前阻止连续提交依赖旧明暗状态的操作。
5. 没有待翻选牌时，执行明确选定的一个行动。跟注与加注根据服务端的 `hasLooked` 使用暗注或明注费用，比牌同样按该状态换算，且须已经进入第三轮；目标不额外付费，弃牌不付费。暗注、明注是费用状态，不是必须依次执行的两个选项。
6. 行动完成后先判断是否只剩一人或触发投入上限；需结束就结算，否则轮到下一名在局者。只翻牌时继续停留在当前回合，玩家可再翻其他牌或执行行动。

例如暗注基准为 2：玩家可以完全不翻牌，直接暗跟 2；也可以选中一张、右键桌子翻开，确认后本回合跟注变为 4。第二次右键必须明确确认跟注才扣 4，不会因为刚才翻过牌就自动下注。

### 视觉实现方案（已接入，待用户实机验收）

整体保留世界画面，普通对局不打开全屏 Screen。配置页复用现有设置页面风格。HUD 顶部只显示公共局势，底部中央显示本人三张手牌及操作条，不设置六人侧边状态列表。对手信息分布到各自的世界位置；避开准星、物品栏及聊天区，随 GUI 缩放与窗口大小计算布局。

- 顶部：炸金花、当前轮次、当前行动者、行动倒计时；另列锅底、暗注基准、本人对应的跟注费用及本桌投入上限。锅底与个人剩余预算明确分开。
- 本人手牌：三个固定牌位，发牌后不因翻牌或按大小重新排序。未翻显示现有牌背，已翻显示对应真实牌面。滚轮焦点用黄框，左键选中用抬升及选中标记，两种效果可以同时存在。已经翻过的牌不可再次选作翻牌请求；非本人回合不显示可翻牌的交互高亮。未选牌位的实际牌面不能提前下发。
- 世界三张牌：复用斗地主现有玩家身前立牌的位置、几何与缓存，跟随玩家移动；仅对仍在局者绘制。牌背表示未翻，`card_empty.png` 表示已翻，按公开数量从左到右替换，不公开实际牌位或牌面。明牌状态与已翻数量由这三张牌直接表达，不在屏幕另放重复列表。
- 世界文字：在该玩家身前牌组的左侧显示“累计投入 N”，右侧显示“上次跟注 N / 上次加注 N / 比牌胜”等最近行动。左右以该玩家牌组的局部坐标为准，跟随玩家，文字面向观察相机以便阅读。当前行动者在牌组上方加“行动中”及醒目边框，与庄家标记区分。
- 庄家标记：在玩家原版头顶名称上方绘制金黄色 `[ 庄 ]` 标记，避免引入字体或大图。庄家身份由服务端明确下发，与当前行动者分开，不因轮到其他人就移动庄家标记。庄位如何轮换仍沿用计划中的首局随机、随后轮换建议，视觉标记不额外授予规则权益。
- 出局显示：服务端确认弃牌或比牌失败后，撤掉该玩家身前三张牌，原牌组位置只显示“出局”，右侧可保留“弃牌 / 比牌失败”原因，左侧保留本局累计投入。不继续显示空牌/牌背，也不公开真实牌。所有人的结算记录独立保留；玩家离线或离开渲染范围时，不伪造一个玩家模型留在原地。
- 世界文字可读性：使用紧凑字号、文字描边或低透明底板，文字按正常世界深度遮挡，不透墙；做距离与视锥裁剪。多人靠得很近时优先显示名字、行动标记及牌组，对其他文字缩短或分行，不能把六人信息重新挤回固定侧栏。由真实六人客户端场景验证重叠问题。
- 操作条：显示实际支付金额；本人回合显示合法行动，第 1、2 轮标注“第三轮可比牌”且不能提交比牌，第 3 轮起解锁。明牌按钮只进入选牌，不直接改变费用；有选牌时明确提示“右键牌桌：翻开已选 N 张”，翻牌确认后刷新明注费用并继续当前回合。手牌区与行动区必须显示不同的焦点标题和当前右键用途，避免同一滚轮产生无法判断的行为；选牌与行动各自使用滚轮，右键空气退出选牌，提示条显示当前焦点用途。
- 世界隐私与筹码：不直接复用斗地主的牌面可见性，任何观察视角包括绕到背后都不得看到对手真实牌面。本人真实手牌以 HUD 为准，本人世界手牌在第一人称不重复绘制；其他玩家的客户端照常看到本人的公开牌背/空牌。筹码启用时桌上复用一个筹码物品模型表示类型，锅底准确数量以 HUD 数字表示，不按筹码数生成实体；关闭物品筹码时不画该物品。
- 比牌：用简短文字指明“甲与乙比牌，乙出局”，不在局中展示双方真实手牌，也不提前显示对方牌型。出局身份和可操作状态与服务端结果同步。
- 结算：切换到居中的半透明结果面板，逐行列出本局全部玩家姓名、三张真实牌、牌型、获胜/出局状态和净得失；2–6 人均要能完整展示，六人小窗口使用紧凑排版而非裁掉行。此时空牌/牌背替换为真实牌面，离开及掉线者也保留记录。正常结束才公开，退款取消不套用结算亮牌。结算不显示滚轮菜单，右键任意位置（包括空气）关闭。

翻牌的画面变化以服务端确认为准；首版可直接替换贴图，不以复杂动画阻塞操作。桌面不绘制斗地主式“最后一手出牌”，因为炸金花没有把牌逐手打到桌面的流程。渲染布局、颜色和动效属于实现建议；已确定的隐私、明暗倍率、翻牌数量与结算全员亮牌不因美术调整改变。

## 4. 代码结构与复用边界

沿用当前源集：无加载器依赖的代码放 `common/src/main/java`，NeoForge 注册和事件接入放 `src/main/java`。本分支只验收 NeoForge 1.21.1。

建议新增的逻辑模块（名称可随实现精简）：

```text
game/cards/           CardCodec：纯 Java 的点数、花色、合法牌检查
game/zjh/             ZJHEngine、牌型分类、双人比较、多人开牌、固定规则常量与动作结果
game/table/           最小公共契约：会话身份、玩家占用、关闭通知
game/server/zjh/      ZJHSession、牌桌管理、逐接收者快照与物品结算
game/server/chips/    ChipEscrow：物品保管、返还、离线待领取记录
client/zjh/           ZJHClientData、ZJHHud、ZJHInput、本桌规则设置
network/payload/      ZJHActionPayload、ZJHStatePayload
```

复用按三层处理：

| 层次 | 做法 |
| --- | --- |
| 直接复用 | 图片、模型、牌背、只读卡牌缓存、布局计算、倒计时纯函数、音乐包加载 |
| 小范围提取 | 牌面编码、世界手牌渲染输入、筹码原物保管、配置锁、会话关闭接收者集合 |
| 游戏独立 | 牌型比较、回合推进、下注规则、赔付政策、隐私政策、HUD 操作、payload 内容 |

公共渲染器接收“玩家位置、牌背/可见牌、布局参数”等渲染数据，不再自行读取斗地主快照或判断斗地主阶段。斗地主通过适配层提供原有数据，先保证画面和行为不变，再接炸金花。

不建立庞大的通用棋牌框架，不把两个规则引擎塞进同一个大类，不为追求少几个类强行共用牌局快照。公共筹码组件只负责保管和交付，斗地主赔付与炸金花分锅各自决定金额。

## 5. 服务端权威、隐私与同步

- 引擎只依赖 Java，保存完整手牌及数字账本；Minecraft 会话负责玩家、距离、物品和生命周期。
- 所有动作从服务端连接取得玩家身份，主线程校验桌块类型、维度、座位、阶段、目标、额度、余额和回合。
- 新游戏用独立消息 ID，不修改旧动作枚举顺序，不借斗地主 `score/cards` 字段传递炸金花下注语义。扩展现有网络接缝以接入新的类型。
- C2S 携带局号和动作序号；状态变化递增版本。陈旧或重复操作拒绝并刷新状态，防止双击重复扣款、旧包作用到下一局。
- 每位接收者独立构建快照。本人只收到已翻牌位的牌面；对手与普通旁观者不收到这些牌面，可以知道该玩家的明暗状态及已翻张数。`hasLooked` 和已翻牌位由服务端维护，客户端不能声明自己仍处于暗牌以降低费用。
- 向同桌玩家及主动观战者公开每位玩家的已翻张数 `revealedCount`（0–3），由服务端已翻牌位集合计数得出，不另外维护可能失配的计数真相。其他人看到的“明牌”表示已看牌的下注状态，公开张数不授予牌面访问权限。世界中的三张状态牌消费该计数；本人 HUD 手牌区仍按已翻牌位显示真实牌面。
- 牌局进行中，首版观战只看公开桌面；不继承斗地主默认允许旁观者看牌的配置。比牌只公布输赢，不自动向全桌发送双方手牌。
- 正常结算时才向本桌结果接收者下发所有原始参局者的完整手牌，用于 HUD 全员亮牌。会话保留独立的本局玩家身份、手牌及结果记录，不随清座位或退场丢失。结算展示的全体手牌不参与重新判胜；退款取消流程不冒充正常结算公开牌面。
- 状态变化时发送全量小快照，倒计时在客户端插值；不每刻广播，不每帧发送交互或重新生成牌面对象。
- 所有移除路径通知参局者、主动观战者、配置锁持有者以及刚离开的玩家；客户端按游戏类型和桌 key 清理缓存。

## 6. 筹码、清退与异常恢复

建议开局时按个人投注上限托管本局预算，每次下注从个人余额转入锅底；结束退还未使用部分。保留这一层是为了避免筹码转移后支付落空，界面必须明确提示“暂存本局预算，结束退还未下注部分”。

- 提交开局前统一验证所有已加入玩家；收取中途失败须回滚全部已收原物，不能出现部分扣款后发牌。
- 保留 `ItemStack` 组件，不把附魔/命名物品重建成白板；可按相同组件合并存储，不必每枚物品都长期占一个对象。
- 游戏逻辑账本使用 `long` 和有上限的检查运算，物品数量单次拆分仍遵守 Minecraft 栈规则。
- 正常结束：赢家获得锅底，退回所有未使用余额；守恒关系为“投注余额 + 锅底 + 已发还物品 = 实收原物总量”。
- 中途退出只损失已下注部分，退回未下注预算。结算记录保留本局所有参与者，不能随着座位清空而删除；不照搬斗地主的判负赔付。
- 拆桌或管理性中止：按贡献记录退还本局已下注及未下注原物，不额外决胜。区块卸载必须明确进入取消/恢复路径，不能让静态会话持有失效方块实体。
- 离线返还按 UUID 记入待领取记录；背包满走受控返还流程，不能漏掉物品或在重复结算时再次发放。
- 托管记录与结算状态必须持久化；服务端正常关闭取消未完成局。重启发现未完成记录时按贡献退款，不恢复一半进行中的牌局。交付记录要防重复执行；异常崩溃跨玩家背包与存档写入的原子性需要专门设计和故障测试，不能仅靠一次 `save()` 宣称绝对安全。

## 7. 包体与性能约束

1. 不添加第三方运行库，不捆绑字体、音频、视频及重复的整套扑克牌资源。
2. 新桌模型优先引用已有纹理，只有识别游戏确实需要时新增小图。保留现有注册 ID，不能为了减体积删掉旧存档需要的渲染器。
3. 首版复用现有通用音效/BGM及回退机制，不新增炸金花专属音频键，不把斗地主牌型语音当作炸金花提示。
4. 世界渲染按座位数量与距离裁剪；最多六人各三张手牌，复用缓存，避免新建卡牌实体和每帧构造 `ItemStack`。
5. 超时沿用低频清扫与明确的行动截止刻，不让看牌、观战刷新或无效包延长时间。
6. 发布包继续排除 GameTest、测试结构和 `.ogg`。检查压缩后条目，记录新增类、资源和最终 ZIP/JAR 的差额。

暂定 JAR 增量目标不超过约 150 KiB，属于待实测预算而非承诺。超出时先定位重复资源和依赖；不为少几 KiB 牺牲隐私、退款可靠性或可维护性。性能报告注明机器、桌数、玩家/观战者数、分辨率、帧时间及服务端耗时，避免空口声称“零开销”。

## 8. 实施阶段与验收

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| 1. 规则定稿 | 基础规则、操作示意、配置默认值 | 普通牌型及特殊 235、第三轮比牌、明暗费用、封顶与平手均有明确答案 |
| 2. 纯 Java 内核 | 牌型比较、2–6 人引擎、数字账本 | 规则单测、所有三张组合分类、随机对局守恒与终止检查通过 |
| 3. 最小公共提取 | 卡牌工具、渲染数据接口、筹码保管、玩家占用 | 原斗地主单测和相关 GameTest 通过，旧配置与旧桌不变 |
| 4. 服务端联机 | 新桌注册、会话、专属网络、托管与恢复 | 多桌隔离、非法包、隐私、退出与退款 GameTest 通过 |
| 5. 客户端体验 | HUD、输入、配置、世界手牌、结算 | 2/3/6 人流程可操作，小窗口不重叠，两种游戏无输入冲突 |
| 6. 发布验收 | 体积差异、性能记录、说明与安装包 | 专用服务器、真实多客户端验收和固定目标构建通过 |

测试重点：

- 枚举 52 选 3 共 22,100 手牌，确认每手唯一分类，不同排列结果一致；普通非特殊牌比较验证传递性，完整双人比较验证特殊循环，多人系统开牌验证手牌输入顺序无关。
- A23 仅次于 QKA；非同花 235 为特殊，同花 235 为金花；特殊与豹子同场参比时特殊获胜，即使还有其他牌型；出局者的豹子不触发之后的系统开牌特例。对子先比对子点数，花色不参与决胜。
- 明暗注额换算、加注只扣一次、比牌费用和平手发起者输、比牌后换人、系统开牌并列及锅底余数分配。
- 前两轮禁止比牌、第三轮放开；只扣发起者两倍跟注费用，目标不扣费；输家弃牌、赢家保留，比牌后不追加行动。轮次不因翻牌或弃牌错误增加/重置。
- 固定上限恰好到达和下一次支付会超限两种结束路径；超限动作不扣费、不出现部分支付；豹子和顺金获胜均只赢锅底，无任何额外收费。
- 翻一张即转明牌、其余未翻牌仍隐藏、不可恢复暗注；翻牌不扣费、不换人、不延期；同次右键只翻牌不下注，确认后费用刷新；重复翻牌不重复产生状态变更，非本人回合不得翻牌。
- 世界状态牌覆盖 0/1/2/3 张翻牌进度，HUD 本人手牌覆盖翻牌后继续跟注/加注；出局撤牌改为“出局”，后台保留本局翻牌记录，新局清零。重复翻同一张不增加计数；一次翻两张按唯一牌位计数。1/2/3 张均为相同明注倍率，进行中其他人的快照只公开数量与行动，不泄露牌面。
- 六人世界显示验证左右文字不严重重叠、当前行动标记与头顶庄家标记互不混淆、距离/遮挡裁剪正常、出局撤牌无残留；不再绘制屏幕侧边六人列表。
- 正常结算 HUD 展示所有原始参局者三张完整手牌，包括暗牌、弃牌、比牌出局及离开者；最后一人直接获胜也全员展示。全员亮牌仅在结算快照出现，展示出局手牌不改变最终赢家。
- 先选牌后右键优先翻牌；无选牌无行动的右键无副作用；翻牌确认前不执行旧价格操作；无效动作和重复包不得扣款，等待期退出与开局失败不留托管。
- 托管原物组件保持、正常结算/离线/拆桌/区块卸载/停服退款、重复恢复不重复发放。
- 一人跨两游戏抢座、两张桌同坐标不同维度、多个桌同时活动、旧斗地主存档和设置回归。
- 快照 NBT 往返与缺省字段；直接检查 payload 中没有不该下发的暗牌。
- GameTest 负责服务端状态；真实客户端负责配置锁关闭、HUD 关闭、渲染和收包体验，不能以模拟连接替代。

按仓库约定，构建前确认开发客户端已退出，避免类文件重写导致客户端崩溃。最终执行固定目标构建脚本，并单独执行目标为 1.21.1 的 GameTest；`build` 成功不代替 GameTest。触及音乐包制作工具时再运行其 Python 测试。

安装包目标仍为 `build/mc-1.21.1/libs/crafty_cards-neoforge-mc1.21.1-1.0.0.jar`。基础实现已落地；自动化测试、打包结果以最新交付报告为准。真实客户端、多客户端对局与视觉效果由用户验收，不能把服务端 GameTest 当作实机通过。
